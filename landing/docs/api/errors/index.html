Delivery and errors

Errors

Error responses are JSON (including API Gateway 401, 403, and 429 responses) and include a human-readable error message, a stable code, requestId, and a retryable boolean. Decoding/validation failures also include field when tied to a specific attribute or header, and render failures may include bounded details.

400 / application/json
{
  "error": "Invalid render request: unknown field \"paperSize\"",
  "code": "render_request_invalid",
  "requestId": "7db7...",
  "field": "paperSize",
  "retryable": false
}

Handling failures

400 / 409 / 413 / 422retryable: false. Correct the offending field, payload, or Idempotency-Key before retrying.
401 / 403retryable: false. Check that the API key is active and sent as Authorization: Bearer <key>.
429 / 503 / 504retryable: true. Respect the Retry-After header (seconds) and retry with exponential backoff; reuse Idempotency-Key for safe retries.
500retryable: true. Retry once for a transient failure; if it persists, retain requestId for support.

The renderer may log further diagnostic detail, but API responses deliberately omit page content, URLs, and browser internals.
