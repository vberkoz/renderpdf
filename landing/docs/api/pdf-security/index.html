Enterprise & security

Document security, redaction & signatures

POST/render

Protect confidential PDFs with military-grade AES-256 encryption, sanitize sensitive PII from document ASTs before Chromium execution, and cryptographically sign contracts with X.509 digital certificates or AWS KMS.

AES-256 password protection & permissions

Adding options.password locks the PDF with standard AES-256 encryption. Set an optional ownerPassword for administrative rights and restrict printing or copying with permissions.

passwordstringoptional

User password required to open and decrypt the document (up to 128 characters).

ownerPasswordstringoptional

Owner password required to change permissions or remove protection. Defaults to password if omitted.

permissionsstringoptional

Permissions granted to users: all (default; full printing and text copying), print (allows high-resolution printing; prevents text extraction), or none (view-only; prevents printing and copying).

cURL · Password-protected document
curl -X POST https://renderpdf.vberkoz.com/api/v1/render \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -d '{
    "version": "1",
    "source": { "type": "html", "content": "<main><h1>Confidential Payroll Statement</h1><p>Employee: {{employee.name}}</p><p>Net Pay: {{payroll.netPay}}</p></main>" },
    "data": { "employee": { "name": "Jane Doe" }, "payroll": { "netPay": "$5,420.00" } },
    "options": {
      "format": "A4",
      "password": "JanePayroll2026!",
      "ownerPassword": "FinanceMasterKey999!",
      "permissions": "print"
    }
  }'

Server-side PII redaction & masking

Unlike client-side visual overlays that merely draw black boxes over selectable text, RenderPDF performs AST-level document sanitization before Chromium rendering or PDF generation. The underlying sensitive characters are excised completely, preventing text extraction, copying, or reverse-engineering from vector streams.

HTML tags & attributes

You can mark elements for redaction directly in your HTML content:

  • <redact style="bar|mask|text" type="ssn|creditCard|email|phone">123-45-6789</redact>
  • <span data-redact="true" data-redact-style="mask" data-redact-type="email">user@example.com</span>

Automated pattern scrubbing (`options.redaction`)

Automatically scrub PII matching built-in detectors or custom regular expressions across the entire document:

enabledbooleanrequired

Set to true to activate automated AST scrubbing.

typesarray of stringsoptional

Built-in PII patterns to sanitize: "ssn", "creditCard", "email", "phone".

patternsarray of stringsoptional

Custom regex patterns to match and excise (e.g. ["CONFIDENTIAL-\\d+", "ACCT-\\w+"]).

replacementstringoptional

Redaction style:

  • bar (default): Renders an opaque solid black block (████) containing zero underlying glyphs.
  • mask: Masks leading digits while preserving trailing characters (e.g. ***-**-6789, ****-****-****-4242, u***@example.com).
  • text: Replaces the match with the custom string specified in replacementText.

replacementTextstringoptional

Custom string used when replacement: "text" (defaults to "[REDACTED]").

cURL · Automated PII redaction
curl -X POST https://renderpdf.vberkoz.com/api/v1/render \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -d '{
    "version": "1",
    "source": {
      "type": "html",
      "content": "<main><h1>Patient Record</h1><p>SSN: 123-45-6789</p><p>Email: patient@clinic.org</p><p>Case: CASE-998811</p></main>"
    },
    "options": {
      "format": "A4",
      "redaction": {
        "enabled": true,
        "types": ["ssn", "email"],
        "patterns": ["CASE-\\d+"],
        "replacement": "bar"
      }
    }
  }'

Cryptographic digital signatures (X.509 PKCS#7)

Stamp legal contracts, NDAs, and official agreements with cryptographic X.509 digital signatures. Verifiable in Adobe Acrobat Reader and PDF viewers with tamper-evident seal and certification status.

certificatestringoptional

Base64-encoded X.509 certificate in PEM or PKCS#12 (.p12/.pfx) format.

privateKeystringoptional

Base64-encoded private key in PEM format (required if certificate is PEM and not using KMS).

passwordstringoptional

Password to decrypt the PKCS#12 archive or encrypted private key.

kmsKeyIdstringoptional

AWS KMS Key ID, Key ARN, or Alias (e.g. arn:aws:kms:us-east-1:123456789012:key/...). Delegates cryptographic hash signing to a cloud HSM, ensuring private keys never leave secure hardware.

namestringoptional

Signer full name displayed in signature properties (e.g. "RenderPDF Legal Representative").

reasonstringoptional

Signing reason or document execution intent (e.g. "Execution of Master Services Agreement").

locationstringoptional

City, state, or country of signature execution.

contactInfostringoptional

Signer contact email or phone.

cURL · Digitally signed contract
curl -X POST https://renderpdf.vberkoz.com/api/v1/render \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -d '{
    "version": "1",
    "source": {
      "type": "html",
      "content": "<main><h1>Services Agreement</h1><p>Signed and certified electronically.</p></main>"
    },
    "options": {
      "format": "A4",
      "signing": {
        "certificate": "MIIDXTCCAkWgAwIBAgIJ...",
        "privateKey": "MIIEvQIBADANBgkqhkiG...",
        "name": "Jane Smith",
        "reason": "Authorized Agreement Signature"
      }
    }
  }'
