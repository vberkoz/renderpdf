Developer reference / v1

RenderPDF API

Turn HTML into downloadable PDFs with one request. Start with the no-key trial endpoint, then move to authenticated generation when you’re ready.

Base URL: https://renderpdf.vberkoz.com/api/v1

Quick trial: POST /trial/render (no key required)

Quick start

Run one request to try RenderPDF without an account, then use the authenticated request below when you have an API key.

curl -X POST https://renderpdf.vberkoz.com/api/v1/trial/render \
  -H "Content-Type: application/json" \
  -d '{"html":"<h1>Hello World</h1>"}'

Render with an API key

Create a key in the dashboard, then use the production endpoint.

curl -X POST https://renderpdf.vberkoz.com/api/v1/render \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -d '{"version":"1","source":{"type":"html","content":"<h1>Hello World</h1>"},"data":{}}'

Render an HTML file

From this repository, use jq to read an HTML file as a JSON string before posting it.

curl -X POST https://renderpdf.vberkoz.com/api/v1/trial/render \
  -H "Content-Type: application/json" \
  --data "$(jq -Rs '{html: .}' /Users/basilsergius/projects/renderpdf/doc-examples/invoice.html)"

Note: The trial allows 3 successful PDFs per public IP per UTC day. Failed renders are refunded automatically.

Request basics

All API routes are relative to https://renderpdf.vberkoz.com/api/v1 and exchange JSON unless the route explicitly returns a presigned upload URL.

  • Content-Type: application/json: Required for requests with a JSON body.
  • Authorization: Bearer <key>: Required for production render, upload, template, and webhook requests.
  • Accept: application/json: Optional; JSON is returned for successful and error responses.

Authentication

The production endpoints require an API key in the Authorization: Bearer request header.

Authorization: Bearer YOUR_API_KEY

Authorization: Bearer YOUR_API_KEY

Do not expose production API keys in client-side code or public repositories.

Anonymous trial (POST /trial/render)

Uses the same renderer without an API key. Trial requests are rate-limited by a privacy-preserving hash of the viewer IP.

  • Daily limit: 3 PDFs
  • HTML size: 1 MB max
  • Reset: 00:00 UTC

Quota response headers

  • X-Trial-Limit: Maximum successful trial renders per day.
  • X-Trial-Remaining: Successful renders remaining for the current UTC day.

Use GET /trial/quota to read the remaining quota for the current source IP without generating a PDF.

Render (POST /render)

The canonical authenticated endpoint selects HTML, Markdown, saved templates or sources, public URLs, or uploaded packages with source.type, then stores the PDF privately and returns a signed download URL.

Request body

source (object, required): A versioned source object. Use { "type": "html", "content": "..." } for controlled HTML/CSS documents, or markdown, template, url, and upload for the matching source mode.

curl -X POST https://renderpdf.vberkoz.com/api/v1/render \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -d '{"version":"1","source":{"type":"html","content":"<main><h1>Invoice #1042</h1></main>"},"data":{}}'

Render an HTML/CSS JSON document (POST /render)

Send HTML structure, CSS, and dynamic values separately. The authenticated endpoint validates the versioned contract, escapes bound values, builds a complete HTML document, and returns the standard PDF response.

  • version (string, required): Supported value is "1".
  • html (string, required unless source is supplied): HTML fragment containing optional {{path.to.value}} bindings.
  • source (object, optional): Mutually exclusive with html.
  • css (string, optional): Document CSS supported by headless Chrome.
  • data (object, required): Nested values for every binding.
  • options (object, optional): format (A4, Letter, Legal) and margin (0–50mm or 0–2in).
curl -X POST https://renderpdf.vberkoz.com/api/v1/render \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -d '{
    "version":"1",
    "source":{"type":"html","content":"<main><h1>{{report.title}}</h1><p>{{customer.name}}</p></main>"},
    "css":"body { font-family: Arial, sans-serif; } h1 { color: #123456; }",
    "data":{"report":{"title":"Monthly report"},"customer":{"name":"Ada & Sons"}},
    "options":{"format":"A4","margin":"18mm"}
  }'

CSS, limits, and security

Page size and margin are generated from options; @page in HTML or CSS is rejected. CSS @import, url(), unsafe legacy expressions, scripts, event-handler attributes, iframe, embed, object, applet, local files, and local or remote assets are rejected. JavaScript is disabled. Normal http, https, mailto, and #anchor links remain allowed.

  • Request / final input: 1 MiB
  • HTML / CSS: 768 / 128 KiB
  • Data: 256 KiB / 10 levels

Render Markdown (POST /render)

Use CommonMark-compatible Markdown when document structure is text-first. Bindings are resolved before conversion, then treated as plain text; raw HTML is disabled.

curl -X POST https://renderpdf.vberkoz.com/api/v1/render \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -d '{"version":"1","source":{"type":"markdown","content":"# {{report.title}}\\n\\n{{report.summary}}"},"css":"body { font-family: Arial, sans-serif; }","data":{"report":{"title":"Monthly report","summary":"Ready for review."}},"options":{"format":"A4","margin":"18mm"}}'

Render a URL (POST /render)

Navigates Chromium to a public webpage before printing it. This preserves the page's original URL context, so relative images, stylesheets, fonts, and scripts can load.

url (string, required): An absolute public http or https URL using port 80 or 443.

curl -X POST https://renderpdf.vberkoz.com/api/v1/render \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -d '{"version":"1","source":{"type":"url","url":"https://example.com/invoice"}}'

Render a local HTML package (POST /render)

Use this authenticated two-step workflow when a document has local CSS, images, fonts, or JavaScript. ZIP files must use relative paths, contain index.html by default, and are limited to 25 MB compressed, 50 MB extracted, and 500 files. Packages are private, expire after one day, and cannot load network resources while rendering.

upload=$(curl -s -X POST https://renderpdf.vberkoz.com/api/v1/files/upload \
  -H "Authorization: Bearer YOUR_API_KEY")
curl -X PUT --upload-file invoice.zip "$(jq -r .uploadUrl <<<"$upload")"
curl -X POST https://renderpdf.vberkoz.com/api/v1/render \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -d "{\"version\":\"1\",\"source\":{\"type\":\"upload\",\"uploadId\":\"$(jq -r .uploadId <<<"$upload")\"}}"

Store HTML templates (CRUD /templates)

Save reusable HTML once, then render it with only variable data. Templates belong to the API-key owner; another customer receives 404 for the same ID.

  • POST /templates: Create with name, type, html, and optional variables.
  • GET /templates: List saved templates.
  • GET /templates/{id}: Read one template.
  • PUT /templates/{id}: Update a template.
  • DELETE /templates/{id}: Delete a template.
curl -X POST https://renderpdf.vberkoz.com/api/v1/templates \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -d '{"name":"Invoice","type":"invoice","html":"<!doctype html><html><body><h1>Invoice {{invoice.number}}</h1><p>{{customer.name}}</p></body></html>","variables":{"invoice":{"number":"INV-1042"},"customer":{"name":"Ada & Sons"}}}'

Render a stored template (POST /render)

Resolve a customer-owned template with nested variables, then receive the normal PDF response.

templateId (string, required) and variables (object, required).

curl -X POST https://renderpdf.vberkoz.com/api/v1/render \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -d '{"version":"1","source":{"type":"template","templateId":"TEMPLATE_ID","variables":{"invoice":{"number":"INV-1042"},"customer":{"name":"Ada & Sons"}}}}'

Saved sources (CRUD /sources)

Save reusable HTML/CSS JSON or Markdown definitions privately, then render them later with per-request data.

  • POST /sources: Create { name, definition }.
  • GET /sources: List owned source metadata.
  • GET /sources/{id}, PUT /sources/{id}, DELETE /sources/{id}.
{
  "version": "1",
  "source": { "type": "stored", "id": "src_..." },
  "data": { "customer": { "name": "Ada" } }
}

Files and private downloads (GET /files)

Uploaded packages, rendered PDFs, and batch ZIPs remain private. File routes authorize every record by API-key owner and issue short-lived signed URLs instead of public object links.

  • POST /files/upload: Issue 15-minute ZIP upload URL.
  • GET /files/{id}/download: Issue 15-minute signed download URL.
  • DELETE /files/{id}: Delete owned file.

Batch rendering (POST /batches)

Submit up to 99 PDFs in one job. A durable DynamoDB outbox dispatches each item to SQS; retries are at-least-once, while conditional worker claims prevent duplicate PDFs.

{
  "version": "1",
  "source": { "type": "stored", "id": "src_..." },
  "items": [
    { "data": { "customer": { "name": "Ada" } } },
    { "data": { "customer": { "name": "Grace" } } }
  ],
  "options": { "webhookUrl": "https://example.com/hooks/render" }
}
  • GET /batches/{id}: Read job state and totals.
  • GET /batches/{id}/items: List item status and file IDs.
  • POST /batches/{id}/cancel: Cancel pending items.
  • GET /batches/{id}/download: Download ZIP of completed PDFs.

Webhooks

Add webhookUrl to an authenticated render request to receive a pdf.completed event after the PDF is stored. Only public HTTPS endpoints on port 443 are accepted.

  • webhookUrl (string, optional): Public HTTPS endpoint.
  • webhookSecret (string, optional): Signs delivery with HMAC-SHA256 in X-RenderPDF-Signature.
{
  "html": "<h1>Invoice</h1>",
  "webhookUrl": "https://webhook.site/YOUR-UNIQUE-ID",
  "webhookSecret": "your-signing-secret"
}

Go

package main

import (
    "bytes"
    "encoding/json"
    "log"
    "net/http"
    "os"
)

type apiResponse struct {
    URL   string `json:"url"`
    Error string `json:"error"`
}

func main() {
    body, _ := json.Marshal(map[string]any{"version": "1", "source": map[string]string{"type": "html", "content": "<h1>Hello World</h1>"}, "data": map[string]string{}})
    request, err := http.NewRequest(http.MethodPost, "https://renderpdf.vberkoz.com/api/v1/render", bytes.NewReader(body))
    if err != nil { log.Fatal(err) }
    request.Header.Set("Content-Type", "application/json")
    request.Header.Set("Authorization", "Bearer "+os.Getenv("RENDERPDF_API_KEY"))

    response, err := http.DefaultClient.Do(request)
    if err != nil { log.Fatal(err) }
    defer response.Body.Close()

    var payload apiResponse
    if err := json.NewDecoder(response.Body).Decode(&payload); err != nil { log.Fatal(err) }
    if response.StatusCode < 200 || response.StatusCode >= 300 {
        log.Fatalf("RenderPDF request failed (%s): %s", response.Status, payload.Error)
    }

    log.Println(payload.URL)
}

C# / .NET 6+

using System.Net.Http.Json;
using System.Text.Json;

using var client = new HttpClient();
using var request = new HttpRequestMessage(HttpMethod.Post, "https://renderpdf.vberkoz.com/api/v1/render")
{
    Content = JsonContent.Create(new { version = "1", source = new { type = "html", content = "<h1>Hello World</h1>" }, data = new { } })
};
request.Headers.Authorization = new System.Net.Http.Headers.AuthenticationHeaderValue("Bearer", Environment.GetEnvironmentVariable("RENDERPDF_API_KEY"));

using var response = await client.SendAsync(request);

var payload = await response.Content.ReadFromJsonAsync<JsonElement>();
if (!response.IsSuccessStatusCode)
{
    var message = payload.TryGetProperty("error", out var error)
        ? error.GetString()
        : $"RenderPDF request failed ({(int)response.StatusCode})";
    throw new HttpRequestException(message);
}

Console.WriteLine(payload.GetProperty("url").GetString());

Java 11+

import java.io.IOException;
import java.net.URI;
import java.net.http.HttpClient;
import java.net.http.HttpRequest;
import java.net.http.HttpResponse;

public class RenderPdf {
    public static void main(String[] args) throws Exception {
        var request = HttpRequest.newBuilder(URI.create("https://renderpdf.vberkoz.com/api/v1/render"))
            .header("Content-Type", "application/json")
            .header("Authorization", "Bearer " + System.getenv("RENDERPDF_API_KEY"))
            .POST(HttpRequest.BodyPublishers.ofString("{\"version\":\"1\",\"source\":{\"type\":\"html\",\"content\":\"<h1>Hello World</h1>\"},\"data\":{}}"))
            .build();

        var response = HttpClient.newHttpClient().send(request, HttpResponse.BodyHandlers.ofString());
        if (response.statusCode() < 200 || response.statusCode() >= 300) {
            throw new IOException("RenderPDF request failed (" + response.statusCode() + "): " + response.body());
        }

        System.out.println(response.body());
    }
}

Response

Successful generate requests return HTTP 200 and a JSON object describing the stored PDF.

FieldDescription
requestIdUnique identifier for this render.
url15-minute signed private download URL for the PDF.
sizeGenerated file size in bytes.
 

{
  "requestId": "7db7...",
  "url": "https://.../7db7.pdf",
  "size": 29827
}

Errors

Error responses are JSON and always include a human-readable error message plus a stable code for programmatic handling.

StatusCodeMeaning
400invalid_requestInvalid JSON, missing HTML, an empty document, or an invalid render URL.
400document_request_invalidMalformed document JSON, wrong field types, trailing JSON, or unknown fields.
401authentication_requiredAuthentication is required for the requested route.
403—Missing, invalid, or inactive API key.
404not_foundThe requested endpoint is unavailable.
413payload_too_largeTrial HTML exceeds 1 MB limit.
413document_*_too_largeDocument request, HTML, CSS, or data exceeds limit.
422document_binding_*A document binding is missing, unused, or malformed.
422document_format_invalid / document_margin_invalidPaper format or margin is unsupported.
422image_loading_failedAn image failed to load while rendering.
422css_parsing_errorChromium reported a CSS parsing error.
422javascript_exceptionThe page raised an uncaught JavaScript exception.
422navigation_failedChromium could not navigate to the requested page.
429rate_limitedDaily trial or monthly account limit reached.
500storage_failed / rendering_failedStorage or unexpected rendering failure.
503service_unavailableA dependent service is temporarily unavailable.

API keys

Authenticated dashboard users can create, list, and revoke keys through the management API.

  • GET /api-keys: List keys
  • POST /api-keys: Create a key
  • DELETE /api-keys/{id}: Revoke a key

All API-key management requests require a Cognito ID token in the Authorization header.

Create a key

curl -X POST https://renderpdf.vberkoz.com/api/v1/api-keys \
  -H "Authorization: Bearer YOUR_COGNITO_ID_TOKEN"

List keys

curl https://renderpdf.vberkoz.com/api/v1/api-keys \
  -H "Authorization: Bearer YOUR_COGNITO_ID_TOKEN"

Revoke a key

curl -X DELETE https://renderpdf.vberkoz.com/api/v1/api-keys/KEY_ID \
  -H "Authorization: Bearer YOUR_COGNITO_ID_TOKEN"
