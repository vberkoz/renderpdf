01 / Start here

Quick start

Use the anonymous endpoint to render a first document without creating an account.

Terminal 
curl -X POST https://renderpdf.vberkoz.com/api/v1/trial/render \
  -H "Content-Type: application/json" \
  -d '{"html":"<h1>Hello World</h1>"}'

Render an HTML file

From this repository, use jq to read an HTML file as a JSON string before posting it.

Terminal 
curl -X POST https://renderpdf.vberkoz.com/api/v1/trial/render \
  -H "Content-Type: application/json" \
  --data "$(jq -Rs '{html: .}' /Users/basilsergius/projects/renderpdf/doc-examples/invoice.html)"
i

The trial allows 3 successful PDFs per public IP per UTC day. Failed renders are refunded automatically.

02 / Access

Authentication

The production endpoints require an API key in the Authorization: Bearer request header.

Authorization required

Bearer followed by your active RenderPDF API key, for example sk_live_....

Header 
Authorization: Bearer YOUR_API_KEY

Do not expose production API keys in client-side code or public repositories.

03 / Endpoint

Render PDF

POST/render

Renders the supplied HTML with headless Chromium, uploads the PDF, and returns its download URL.

Request body

html string required

The complete HTML document or fragment to render.

cURL 
curl -X POST https://renderpdf.vberkoz.com/api/v1/render \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -d '{"html":"<main><h1>Invoice #1042</h1></main>"}'

04 / Endpoint

Render a URL

POST/render-url

Navigates Chromium to a public webpage before printing it. This preserves the page's original URL context, so relative images, stylesheets, fonts, and scripts can load.

url string required

An absolute public http or https URL using port 80 or 443.

cURL
curl -X POST https://renderpdf.vberkoz.com/api/v1/render-url \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -d '{"url":"https://example.com/invoice"}'
i

This endpoint is authenticated. Localhost, private, link-local, and non-HTTP(S) initial URLs are rejected. Pages that require sign-in, block automated browsers, or load slowly may not render as expected.

05 / Package workflow

Render a local HTML package

POST/render-upload

Use this authenticated two-step workflow when a document has local CSS, images, fonts, or JavaScript. ZIP files must use relative paths, contain index.html by default, and are limited to 25 MB compressed, 50 MB extracted, and 500 files. Packages are private, expire after one day, and cannot load network resources while rendering.

cURL
upload=$(curl -s -X POST https://renderpdf.vberkoz.com/api/v1/uploads \
  -H "Authorization: Bearer YOUR_API_KEY")
curl -X PUT --upload-file invoice.zip "$(jq -r .uploadUrl <<<"$upload")"
curl -X POST https://renderpdf.vberkoz.com/api/v1/render-upload \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -d "{\"uploadId\":\"$(jq -r .uploadId <<<"$upload")\"}"

05 / Async delivery

Webhooks

Add webhookUrl to an authenticated render request to receive a pdf.completed event after the PDF is stored. Only public HTTPS endpoints on port 443 are accepted.

webhookUrlstringoptional

The public HTTPS endpoint to receive the completion event.

webhookSecretstringoptional

Signs each delivery in X-RenderPDF-Signature using HMAC-SHA256 over <timestamp>.<raw body>.

{
  "html": "<h1>Invoice</h1>",
  "webhookUrl": "https://example.com/hooks/renderpdf",
  "webhookSecret": "your-signing-secret"
}

Delivery happens asynchronously. A non-2xx response is retried up to four times before being moved to RenderPDF's delivery dead-letter queue.

06 / Examples

Language examples

Set RENDERPDF_API_KEY in your server environment before running an example. Each example prints the PDF URL on success and reports the API error message for a non-2xx response.

Node.js 18+
const response = await fetch("https://renderpdf.vberkoz.com/api/v1/render", {

const payload = await response.json().catch(() => ({}));

  throw new Error(payload.error || `RenderPDF request failed (${response.status})`);
}

console.log(payload.url);

Go
package main

import (
    "bytes"
    "encoding/json"
    "log"
    "net/http"
    "os"
)

type apiResponse struct {
    URL   string `json:"url"`
    Error string `json:"error"`
}

func main() {
    body, _ := json.Marshal(map[string]string{"html": "<h1>Hello World</h1>"})
    request, err := http.NewRequest(http.MethodPost, "https://renderpdf.vberkoz.com/api/v1/render", bytes.NewReader(body))
    if err != nil { log.Fatal(err) }
    request.Header.Set("Content-Type", "application/json")
    request.Header.Set("Authorization", "Bearer "+os.Getenv("RENDERPDF_API_KEY"))

    response, err := http.DefaultClient.Do(request)
    if err != nil { log.Fatal(err) }
    defer response.Body.Close()

    var payload apiResponse
    if err := json.NewDecoder(response.Body).Decode(&payload); err != nil { log.Fatal(err) }
    if response.StatusCode < 200 || response.StatusCode >= 300 {
        log.Fatalf("RenderPDF request failed (%s): %s", response.Status, payload.Error)
    }

    log.Println(payload.URL)
}

Java 11+
import java.io.IOException;
import java.net.URI;
import java.net.http.HttpClient;
import java.net.http.HttpRequest;
import java.net.http.HttpResponse;

public class RenderPdf {
    public static void main(String[] args) throws Exception {
        var request = HttpRequest.newBuilder(URI.create("https://renderpdf.vberkoz.com/api/v1/render"))
            .header("Content-Type", "application/json")
            .header("Authorization", "Bearer " + System.getenv("RENDERPDF_API_KEY"))
            .POST(HttpRequest.BodyPublishers.ofString("{\"html\":\"<h1>Hello World</h1>\"}"))
            .build();

        var response = HttpClient.newHttpClient().send(request, HttpResponse.BodyHandlers.ofString());
        if (response.statusCode() < 200 || response.statusCode() >= 300) {
            throw new IOException("RenderPDF request failed (" + response.statusCode() + "): " + response.body());
        }

        System.out.println(response.body()); // JSON includes requestId, url, and size
    }
}

07 / Endpoint

Anonymous trial

POST/trial/render

Uses the same renderer without an API key. Trial requests are rate-limited by a privacy-preserving hash of the viewer IP.

Daily limit 3 PDFs
HTML size 1 MB max
Reset 00:00 UTC

Quota response headers

X-Trial-LimitMaximum successful trial renders per day.
X-Trial-RemainingSuccessful renders remaining for the current UTC day.

Use GET /trial/quota to read the remaining quota for the current source IP without generating a PDF. It returns {"limit": 3, "remaining": 2}.

08 / Output

Response

Successful generate requests return HTTP 200 and a JSON object describing the stored PDF.

requestIdUnique identifier for this render.
urlPublic S3 download URL for the PDF.
sizeGenerated file size in bytes.
200 / application/json
{
  "requestId": "7db7...",
  "url": "https://.../7db7.pdf",
  "size": 29827
}

09 / Failures

Errors

Error responses include a short message in error. Rendering failures also include a stable code value, so clients can handle a specific cause without matching message text.

422 / application/json
{
  "error": "An image failed to load while rendering the page",
  "code": "image_loading_failed"
}
StatusCodeMeaning
400—Invalid JSON, missing HTML, an empty document, or an invalid render URL.
403—Missing, invalid, or inactive API key.
404—The requested endpoint is unavailable or does not exist in this deployment mode.
413—Trial HTML exceeds the 1 MB limit.
422image_loading_failedAn image resource could not be loaded while rendering.
422css_parsing_errorChromium reported a CSS parsing error.
422javascript_exceptionThe page raised an uncaught JavaScript exception.
422navigation_failedChromium could not navigate to the requested page.
429—Daily anonymous trial limit reached.
500—An unexpected rendering or storage failure occurred.
503—Trial capacity is busy; retry shortly.
504navigation_timeoutThe page did not finish navigating before the render deadline.
504chromium_timeoutChromium timed out while starting or generating the PDF.

The renderer may log further diagnostic detail, but API responses deliberately omit page content, URLs, and browser internals.

10 / Management

API keys

Authenticated dashboard users can create, list, and revoke keys through the management API.

GET/api-keys

List keys

POST/api-keys

Create a key

DELETE/api-keys/{id}

Revoke a key

All API-key management requests require a Cognito ID token in the Authorization header. Obtain it by signing in to the dashboard; API keys cannot manage other API keys.

Create a key

POST /api-keys has no request body. The plaintext key is returned only in this response, so store it securely.

cURL
curl -X POST https://renderpdf.vberkoz.com/api/v1/api-keys \
  -H "Authorization: Bearer YOUR_COGNITO_ID_TOKEN"
200 / application/json
{
  "keyId": "5d1d...",
  "apiKey": "sk_live_..."
}

List keys

cURL
curl https://renderpdf.vberkoz.com/api/v1/api-keys \
  -H "Authorization: Bearer YOUR_COGNITO_ID_TOKEN"
200 / application/json
{
  "keys": [
    {
      "keyId": "5d1d...",
      "createdAt": 1754371200,
      "lastUsed": 1754374800,
      "isActive": true
    }
  ]
}

createdAt and lastUsed are Unix timestamps in seconds. lastUsed is omitted until the key is used.

Revoke a key

cURL
curl -X DELETE https://renderpdf.vberkoz.com/api/v1/api-keys/KEY_ID \
  -H "Authorization: Bearer YOUR_COGNITO_ID_TOKEN"

A successful revoke returns 204 No Content. The key remains in the list with isActive: false and can no longer authorize PDF generation.

i

API-key management uses the dashboard login session, not an API key.
