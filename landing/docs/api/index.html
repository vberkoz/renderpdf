Get started

Quick start

Run one request to try RenderPDF without an account, then use the authenticated request below when you have an API key.

Terminal 
curl -X POST https://renderpdf.vberkoz.com/api/v1/trial/render \
  -H "Content-Type: application/json" \
  -d '{"html":"<h1>Hello World</h1>"}'

Render with an API key

Create a key in the dashboard, then use the production endpoint.

Terminal 
curl -X POST https://renderpdf.vberkoz.com/api/v1/render \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -d '{"version":"1","source":{"type":"html","content":"<h1>Hello World</h1>"},"data":{}}'

Render an HTML file

From this repository, use jq to read an HTML file as a JSON string before posting it.

Terminal 
curl -X POST https://renderpdf.vberkoz.com/api/v1/trial/render \
  -H "Content-Type: application/json" \
  --data "$(jq -Rs '{html: .}' /Users/basilsergius/projects/renderpdf/doc-examples/invoice.html)"
i

The trial allows 3 successful PDFs per public IP per UTC day. Failed renders are refunded automatically.

When you are ready for production, create an API key in the dashboard, switch the path to /render, and send the key in the Authorization header.

Get started

Request basics

All API routes are relative to https://renderpdf.vberkoz.com/api/v1 and exchange JSON unless the route explicitly returns a presigned upload URL.

Content-Type: application/jsonRequired for requests with a JSON body.
Authorization: Bearer <key>Required for production render, upload, template, and webhook requests.
Accept: application/jsonOptional; JSON is returned for successful and error responses.
i

Keep API keys on a trusted server. Browser code should call your backend rather than embed a production key.

Get started

Authentication

The production endpoints require an API key in the Authorization: Bearer request header.

Authorization required

Bearer followed by your active RenderPDF API key, for example sk_live_....

Header 
Authorization: Bearer YOUR_API_KEY

Do not expose production API keys in client-side code or public repositories.

Get started

Anonymous trial

POST/trial/render

Uses the same renderer without an API key. Trial requests are rate-limited by a privacy-preserving hash of the viewer IP.

Daily limit 3 PDFs
HTML size 1 MB max
Reset 00:00 UTC

Quota response headers

X-Trial-LimitMaximum successful trial renders per day.
X-Trial-RemainingSuccessful renders remaining for the current UTC day.

Use GET /trial/quota to read the remaining quota for the current source IP without generating a PDF. It returns {"limit": 3, "remaining": 2}.

Render inputs

Render

POST/render

The canonical authenticated endpoint selects HTML, Markdown, saved templates or sources, public URLs, or uploaded packages with source.type, then stores the PDF privately and returns a signed download URL.

Request body

source object required

A versioned source object. Use { "type": "html", "content": "..." } for controlled HTML/CSS documents, or markdown, template, url, and upload for the matching source mode.

cURL 
curl -X POST https://renderpdf.vberkoz.com/api/v1/render \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -d '{"version":"1","source":{"type":"html","content":"<main><h1>Invoice #1042</h1></main>"},"data":{}}'

Render inputs

Render an HTML/CSS JSON document

POST/render

Send HTML structure, CSS, and dynamic values separately. The authenticated endpoint validates the versioned contract, escapes bound values, builds a complete HTML document, and returns the standard PDF response.

versionstringrequired

Contract version. The only supported value is "1".

htmlstringrequired unless source is supplied

A non-empty HTML fragment containing optional {{path.to.value}} bindings.

sourceobjectoptional

Mutually exclusive with html. The Markdown shape is { type: "markdown", content: "..." }; it is converted to HTML with raw HTML disabled.

cssstringoptional

Document CSS supported by headless Chrome, subject to the restrictions below.

dataobjectrequired

Nested values for every binding. Missing values, unused leaves, and malformed bindings return 422; inserted values are HTML-escaped.

optionsobjectoptional

format may be A4, Letter, or Legal. margin accepts 0–50mm or 0–2in. Defaults are A4 and 18mm.

cURL
curl -X POST https://renderpdf.vberkoz.com/api/v1/render \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -d '{
    "version":"1",
    "source":{"type":"html","content":"<main><h1>{{report.title}}</h1><p>{{customer.name}}</p></main>"},
    "css":"body { font-family: Arial, sans-serif; } h1 { color: #123456; }",
    "data":{"report":{"title":"Monthly report"},"customer":{"name":"Ada & Sons"}},
    "options":{"format":"A4","margin":"18mm"}
  }'

CSS, limits, and security

Page size and margin are generated from options; @page in HTML or CSS is rejected. CSS @import, url(), unsafe legacy expressions, scripts, event-handler attributes, iframe, embed, object, applet, local files, and local or remote assets are rejected. JavaScript is disabled. Normal http, https, mailto, and #anchor links remain allowed.

Request / final input1 MiB
HTML / CSS768 / 128 KiB
Data256 KiB / 10 levels

Optional webhookUrl and webhookSecret fields use the same signed pdf.completed delivery flow as other authenticated render endpoints.

Render inputs

Render Markdown

POST/render

Use CommonMark-compatible Markdown when document structure is text-first. Bindings are resolved before conversion, then treated as plain text; raw HTML is disabled.

cURL
curl -X POST https://renderpdf.vberkoz.com/api/v1/render \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -d '{"version":"1","source":{"type":"markdown","content":"# {{report.title}}\\n\\n{{report.summary}}"},"css":"body { font-family: Arial, sans-serif; }","data":{"report":{"title":"Monthly report","summary":"Ready for review."}},"options":{"format":"A4","margin":"18mm"}}'

Tables, strikethrough, and task lists are supported. Markdown is limited to 768 KiB; the same CSS, binding, page-option, and private-PDF rules apply.

Render inputs

Render a URL

POST/render

Navigates Chromium to a public webpage before printing it. This preserves the page's original URL context, so relative images, stylesheets, fonts, and scripts can load.

url string required

An absolute public http or https URL using port 80 or 443.

cURL
curl -X POST https://renderpdf.vberkoz.com/api/v1/render \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -d '{"version":"1","source":{"type":"url","url":"https://example.com/invoice"}}'
i

This endpoint is authenticated. Localhost, private, link-local, and non-HTTP(S) initial URLs are rejected. Pages that require sign-in, block automated browsers, or load slowly may not render as expected.

Render inputs

Render a local HTML package

POST/render

Use this authenticated two-step workflow when a document has local CSS, images, fonts, or JavaScript. ZIP files must use relative paths, contain index.html by default, and are limited to 25 MB compressed, 50 MB extracted, and 500 files. Packages are private, expire after one day, and cannot load network resources while rendering.

cURL
upload=$(curl -s -X POST https://renderpdf.vberkoz.com/api/v1/files/upload \
  -H "Authorization: Bearer YOUR_API_KEY")
curl -X PUT --upload-file invoice.zip "$(jq -r .uploadUrl <<<"$upload")"
curl -X POST https://renderpdf.vberkoz.com/api/v1/render \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -d "{\"version\":\"1\",\"source\":{\"type\":\"upload\",\"uploadId\":\"$(jq -r .uploadId <<<"$upload")\"}}"

Reusable assets and batch work

Store HTML templates

CRUD/templates

Save reusable HTML once, then render it with only variable data. Templates belong to the API-key owner; another customer receives 404 for the same ID.

POST /templatesAPI key

Create with name, type, html, and optional default variables. Default data must match the template placeholders. Types are invoice, contract, certificate, receipt, or custom. Returns 201.

GET /templatesAPI key

Lists your saved templates plus bundled starter schemas.

GET /templates/{id}API key

Reads one owned template.

PUT /templates/{id}API key

Replaces name, type, HTML, and default variables; version increments.

DELETE /templates/{id}API key

Deletes an owned template and returns 204.

cURL
curl -X POST https://renderpdf.vberkoz.com/api/v1/templates \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -d '{"name":"Invoice","type":"invoice","html":"<!doctype html><html><body><h1>Invoice {{invoice.number}}</h1><p>{{customer.name}}</p></body></html>","variables":{"invoice":{"number":"INV-1042"},"customer":{"name":"Ada & Sons"}}}'

Starter variable schemas

  • Invoice: invoice.number, invoice.issueDate, invoice.dueDate, invoice.description, invoice.total, customer.name, customer.address.
  • Contract: contract.title, contract.date, contract.scope, contract.startDate, contract.endDate, contract.paymentTerms, party.one.name, party.two.name.
  • Certificate: certificate.title, certificate.achievement, certificate.date, certificate.number, recipient.name.
  • Receipt: merchant.name, merchant.address, receipt.number, receipt.date, receipt.description, receipt.amount, receipt.total, customer.name.
i

Limits: 100 templates per owner, 1 MiB of HTML, and 256 KiB of default variables per template. Values are HTML escaped; raw HTML variable interpolation is unsupported.

Reusable assets and batch work

Render a stored template

POST/render

Resolve a customer-owned template with nested variables, then receive the normal PDF response.

templateIdstringrequired

The ID returned by POST /templates.

variablesobjectrequired

Nested values matching every {{path.to.value}} placeholder. Missing or additional leaves return 422.

cURL
curl -X POST https://renderpdf.vberkoz.com/api/v1/render \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -d '{"version":"1","source":{"type":"template","templateId":"TEMPLATE_ID","variables":{"invoice":{"number":"INV-1042"},"customer":{"name":"Ada & Sons"}}}}'

HTML source example

  1. Move stable HTML into POST /templates.
  2. Replace dynamic text with {{path.to.value}}.
  3. Save the returned template ID in application configuration.
  4. Send templateId and variables instead of full HTML.
  5. Handle 422 by adding missing values or removing extras.

Invoice, Contract, Certificate, and Receipt starter schemas are returned by GET /templates.

Reusable assets and batch work

Saved sources

CRUD/sources

Save reusable HTML/CSS JSON or Markdown definitions privately, then render them later with per-request data. Source definitions are never returned in list or metadata responses.

POST /sourcesAPI key

Create { name, definition }, where definition is a version-1 HTML or Markdown render request without webhook settings.

GET /sourcesAPI key

List owned source metadata. Use GET, PUT, or DELETE /sources/{id} for one source.

{
  "version": "1",
  "source": { "type": "stored", "id": "src_..." },
  "data": { "customer": { "name": "Ada" } }
}

Render this payload through POST /render. Sources are limited to 100 definitions and 25 MiB total per account.

Reusable assets and batch work

Files and private downloads

GET/files

Uploaded packages, rendered PDFs, and batch ZIPs remain private. File routes authorize every record by API-key owner and issue short-lived signed URLs instead of public object links.

POST /files/uploadAPI key

Issue a 15-minute ZIP upload URL. Packages are limited to 25 MiB compressed, 50 MiB extracted, and 500 files.

GET /files/{id}/downloadAPI key

Issue a 15-minute signed download URL for an owned file.

DELETE /files/{id}API key

Delete owned metadata and its private object. PDFs retain for up to 30 days; uploads retain for one day.

Reusable assets and batch work

Batch rendering

POST/batches

Submit up to 99 PDFs in one job. A durable DynamoDB outbox dispatches each item to SQS; retries are at-least-once, while conditional worker claims prevent duplicate PDFs.

{
  "version": "1",
  "source": { "type": "stored", "id": "src_..." },
  "items": [
    { "data": { "customer": { "name": "Ada" } } },
    { "data": { "customer": { "name": "Grace" } } }
  ],
  "options": { "webhookUrl": "https://example.com/hooks/render" }
}
GET /batches/{id}API key

Read job state, totals, progress, and timestamps.

GET /batches/{id}/itemsAPI key

List item status and output file IDs.

POST /batches/{id}/cancelAPI key

Cancel pending items; active work completes safely.

GET /batches/{id}/downloadAPI key

Create or reuse a private ZIP of completed PDFs, up to 100 MiB.

A job-level webhook emits one terminal batch.completed or batch.failed event. Permanently failing worker items are reconciled through the batch dead-letter queue.

Delivery and errors

Webhooks

Add webhookUrl to an authenticated render request to receive a pdf.completed event after the PDF is stored. Only public HTTPS endpoints on port 443 are accepted. For a quick test, create a unique endpoint at Webhook.site.

webhookUrlstringoptional

The public HTTPS endpoint to receive the completion event.

webhookSecretstringoptional

Signs each delivery in X-RenderPDF-Signature using HMAC-SHA256 over <timestamp>.<raw body>.

{
  "html": "<h1>Invoice</h1>",
  "webhookUrl": "https://webhook.site/YOUR-UNIQUE-ID",
  "webhookSecret": "your-signing-secret"
}

Delivery happens asynchronously. A non-2xx response is retried up to four times before being moved to RenderPDF's delivery dead-letter queue.

Language examples

Language examples

These are direct HTTP examples, not official SDKs. Set RENDERPDF_API_KEY in your server environment before running one. Each example prints the PDF URL on success and reports the API error message for a non-2xx response.

Node.js 18+
const response = await fetch("https://renderpdf.vberkoz.com/api/v1/render", {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
    "Authorization": `Bearer ${process.env.RENDERPDF_API_KEY}`
  },
  body: JSON.stringify({ version: "1", source: { type: "html", content: "<h1>Hello World</h1>" }, data: {} })
});

const payload = await response.json().catch(() => ({}));
if (!response.ok) {
  throw new Error(payload.error || `RenderPDF request failed (${response.status})`);
}

console.log(payload.url);

Go
package main

import (
    "bytes"
    "encoding/json"
    "log"
    "net/http"
    "os"
)

type apiResponse struct {
    URL   string `json:"url"`
    Error string `json:"error"`
}

func main() {
    body, _ := json.Marshal(map[string]any{"version": "1", "source": map[string]string{"type": "html", "content": "<h1>Hello World</h1>"}, "data": map[string]string{}})
    request, err := http.NewRequest(http.MethodPost, "https://renderpdf.vberkoz.com/api/v1/render", bytes.NewReader(body))
    if err != nil { log.Fatal(err) }
    request.Header.Set("Content-Type", "application/json")
    request.Header.Set("Authorization", "Bearer "+os.Getenv("RENDERPDF_API_KEY"))

    response, err := http.DefaultClient.Do(request)
    if err != nil { log.Fatal(err) }
    defer response.Body.Close()

    var payload apiResponse
    if err := json.NewDecoder(response.Body).Decode(&payload); err != nil { log.Fatal(err) }
    if response.StatusCode < 200 || response.StatusCode >= 300 {
        log.Fatalf("RenderPDF request failed (%s): %s", response.Status, payload.Error)
    }

    log.Println(payload.URL)
}

Java 11+
import java.io.IOException;
import java.net.URI;
import java.net.http.HttpClient;
import java.net.http.HttpRequest;
import java.net.http.HttpResponse;

public class RenderPdf {
    public static void main(String[] args) throws Exception {
        var request = HttpRequest.newBuilder(URI.create("https://renderpdf.vberkoz.com/api/v1/render"))
            .header("Content-Type", "application/json")
            .header("Authorization", "Bearer " + System.getenv("RENDERPDF_API_KEY"))
            .POST(HttpRequest.BodyPublishers.ofString("{\"version\":\"1\",\"source\":{\"type\":\"html\",\"content\":\"<h1>Hello World</h1>\"},\"data\":{}}"))
            .build();

        var response = HttpClient.newHttpClient().send(request, HttpResponse.BodyHandlers.ofString());
        if (response.statusCode() < 200 || response.statusCode() >= 300) {
            throw new IOException("RenderPDF request failed (" + response.statusCode() + "): " + response.body());
        }

        System.out.println(response.body()); // JSON includes requestId, url, and size
    }
}

Delivery and errors

Response

Successful generate requests return HTTP 200 and a JSON object describing the stored PDF.

Successful render response fields
FieldDescription
requestIdUnique identifier for this render.
url15-minute signed private download URL for the PDF.
sizeGenerated file size in bytes.
200 / application/json
{
  "requestId": "7db7...",
  "url": "https://.../7db7.pdf",
  "size": 29827
}

Store requestId with your job or invoice record. It is the best identifier to include when reporting a rendering issue.

Delivery and errors

Errors

Error responses are JSON and always include a human-readable error message plus a stable code for programmatic handling. When a request reaches the API service, it also includes requestId; retain it when contacting support.

422 / application/json
{
  "error": "An image failed to load while rendering the page",
  "code": "image_loading_failed",
  "requestId": "7db7..."
}
API errors
StatusCodeMeaning
400invalid_requestInvalid JSON, missing HTML, an empty document, or an invalid render URL.
400document_request_invalidMalformed document JSON, wrong field types, trailing JSON, or unknown fields.
401authentication_requiredAuthentication is required for the requested route.
403—Missing, invalid, or inactive API key; this response is produced by API Gateway before the request reaches the service.
404not_foundThe requested endpoint is unavailable or does not exist in this deployment mode.
413payload_too_largeTrial HTML exceeds the 1 MB limit.
413document_*_too_largeDocument request, HTML, CSS, data, or compiled renderer input exceeds its documented limit.
422document_binding_*A document binding is missing, unused, or malformed.
422document_format_invalid / document_margin_invalidPaper format or margin is unsupported.
422document_*_unsafe / document_asset_disallowed / document_page_settings_disallowedDocument HTML, CSS, URL, asset, or page settings violate the security policy.

422navigation_failedChromium could not navigate to the requested page.

500rendering_failedAn unexpected rendering failure occurred.

Handling failures

400 / 413 / 422Correct the request or document before trying again. Do not retry unchanged input.
403Check that the API key is present, active, and sent as Authorization: Bearer <key>.
429 / 503 / 504Wait and retry with exponential backoff. Preserve the original input so the retry is identical.
500Retry once for a transient failure; if it persists, retain the response and request details for support.

The renderer may log further diagnostic detail, but API responses deliberately omit page content, URLs, and browser internals.

API key management

API keys

Authenticated dashboard users can create, list, and revoke keys through the management API.

GET/api-keys

List keys

POST/api-keys

Create a key

DELETE/api-keys/{id}

Revoke a key

All API-key management requests require a Cognito ID token in the Authorization header. Obtain it by signing in to the dashboard; API keys cannot manage other API keys.

Create a key

POST /api-keys has no request body. The plaintext key is returned only in this response, so store it securely.

cURL
curl -X POST https://renderpdf.vberkoz.com/api/v1/api-keys \
  -H "Authorization: Bearer YOUR_COGNITO_ID_TOKEN"
200 / application/json
{
  "keyId": "5d1d...",
  "apiKey": "sk_live_..."
}

List keys

cURL
curl https://renderpdf.vberkoz.com/api/v1/api-keys \
  -H "Authorization: Bearer YOUR_COGNITO_ID_TOKEN"
200 / application/json
{
  "keys": [
    {
      "keyId": "5d1d...",
      "createdAt": 1754371200,
      "lastUsed": 1754374800,
      "isActive": true
    }
  ]
}

createdAt and lastUsed are Unix timestamps in seconds. lastUsed is omitted until the key is used.

Revoke a key

cURL
curl -X DELETE https://renderpdf.vberkoz.com/api/v1/api-keys/KEY_ID \
  -H "Authorization: Bearer YOUR_COGNITO_ID_TOKEN"

A successful revoke returns 204 No Content. The key remains in the list with isActive: false and can no longer authorize PDF generation.

i

API-key management uses the dashboard login session, not an API key.
