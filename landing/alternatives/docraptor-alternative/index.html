Frequently Asked Questions

Common questions from developers migrating from DocRaptor to RenderPDF.

Why should I switch from DocRaptor to RenderPDF?

DocRaptor relies on PrinceXML, a proprietary print formatter that behaves differently from modern web browsers. CSS Grid, modern Flexbox layouts, web fonts, and SVG graphics often require idiosyncratic workarounds. RenderPDF runs genuine headless Chromium, meaning your documents render with pixel precision identical to what you see in desktop Chrome, at an 80%+ cost savings.

How does RenderPDF handle page breaks and headers/footers?

RenderPDF supports standard CSS page break controls including break-inside: avoid;, page-break-before, and page-break-after. For dynamic headers and footers with page numbers, you can supply options.headerTemplate and options.footerTemplate with native Chromium counters like <span class="pageNumber"></span>.

Can I test RenderPDF without a credit card or account?

Yes! RenderPDF provides an open trial endpoint (POST /api/v1/trial/render) that allows 3 free renders every day per IP address with zero authentication, no API keys, and no credit card required. You can also test in the interactive browser playground on our homepage.

What paper sizes and security features are supported?

We support A4, Letter, and Legal paper sizes in portrait and landscape orientations. For security, RenderPDF includes native AES-256 PDF encryption via options.password, allowing you to password-protect documents and restrict print or copy permissions.
