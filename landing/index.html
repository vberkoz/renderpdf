import os
import requests

response = requests.post(
    "https://renderpdf.vberkoz.com/api/v1/render",
    headers={
        "Authorization": f"Bearer {os.environ['RENDERPDF_API_KEY']}",
        "Content-Type": "application/json"
    },
    json={
        "source": {
            "type": "html",
            "content": "<h1>Boarding Pass</h1><qrcode value=\"FL-8821\" size=\"140\" />"
        },
        "options": {
            "format": "A4",
            "pageNumbers": { "format": "Page {page} of {total}", "position": "bottom-right" }
        }
    }
)

download_url = response.json()["url"]
print(f"Generated PDF: {download_url}")

How does RenderPDF handle custom CSS and web fonts?

RenderPDF runs headless Chromium with full support for CSS Grid, Flexbox, CSS custom properties, and page-break rules. Page layout behavior depends on the render mode: in sandboxed Document JSON (html with data or css) and markdown modes, author @page rules are disallowed (HTTP 422) — configure paper size, margins, and orientation via options.format, options.margin, and options.landscape. In plain html, template, url, and upload modes, @page CSS is supported when page options are omitted (explicit options override @page).

Pre-installed container fonts (Inter, Roboto, Open Sans, Lato, Montserrat, IBM Plex Sans/Mono, DM Sans, and Noto Sans CJK/Arabic/Emoji) work across all modes. External font stylesheets (such as Google Fonts or @font-face URLs) and base64 data: fonts work in plain html, template, and url modes; ZIP upload packages support local font files and base64 data: fonts (external CDNs are blocked by package CSP); sandboxed Document JSON and markdown modes block external <link>, @import, and CSS url() assets.

Is my document data stored or shared?

Your documents are completely private. We never share, sell, or use your data to train AI models.

Rendered PDFs are stored in private, AES-256 encrypted AWS S3 buckets and can only be downloaded via short-lived presigned URLs that expire after 15 minutes. All generated PDFs and temporary upload packages are governed by automatic 30-day deletion lifecycle policies—once the 30-day window passes, objects are permanently removed.
